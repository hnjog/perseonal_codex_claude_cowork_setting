## 공통 규칙의 핵심 확인 항목

- 조사와 계획
  - 관련 파일과 실제 호출부 확인 후 타당한 대안 2~3개 및 추천 이유 제시
  - 기존 구현의 목적·책임·실행 문맥·수명·부작용까지 확인하여 재사용 판단
  - 계획서에 실제 파일 경로·영향·검증 방법·장단점 포함
- 코드 수정 승인
  - 방향 선택과 실제 수정 승인을 구분
  - 수정 전 대상 파일·범위·변경 코드 또는 diff 제시
  - 명시적으로 승인된 범위 안에서만 수정 / 범위 밖 변경은 추가 승인
  - 교대 자체를 새 코드 수정 승인으로 해석하지 않기
- 구현
  - OOP와 팀 코딩 컨벤션 준수 / 과도한 클래스 분리는 사전 확인
  - 기존 클래스 전체의 리팩터링으로 범위 확대 금지
  - 데이터 식별자와 문자열 계약을 임의 추가하지 않기
  - 신규 설명 주석은 기본적으로 추가하지 않고 명확한 이름과 구조 우선
- Git
  - 별도 지시 없는 Git 상태 변경과 자동 커밋·푸시·PR 생성 금지
  - 교대를 위한 커밋·브랜치 변경·stash 자동 실행 금지
  - 커밋 제목·본문과 PR 제목은 영어
- 문서와 보고
  - 별도 위치 지정이 없으면 `C:\Projects\Contexts\docs`에 저장
  - Notion용 계획서는 짧은 구절·명사형 종결과 들여쓰기 목록 사용 / 항목 끝 마침표 금지
  - 별도 요청 없는 Notion 페이지 생성·게시 금지
  - 실제 검증 결과와 미수행 테스트 구분

## 교대 절차

- 작업 종료 측
  - 편집과 실행 중인 명령의 상태 확인 / 진행 중인 작업이 있으면 인계에 명시
  - 작업별 인계 문서를 현재 상태 중심으로 갱신
  - 수정 중인 동일 파일을 다음 도구가 동시에 편집하지 않도록 작업 중단 시점 명시
- 작업 시작 측
  - 공통 지침과 해당 작업 인계 문서 읽기
  - 실제 작업 폴더와 읽기·쓰기 권한 확인
  - 관련 파일의 현재 상태 확인 / 필요 시 읽기 전용 Git 조회
  - 다른 도구나 사용자의 기존 변경 보존 / 파일의 작성자나 변경 의도 추정 금지
  - 사용자 승인 근거와 범위가 분명하면 해당 범위 내에서 이어서 작업
  - 승인 근거가 누락되거나 제안한 변경이 달라지면 필요한 승인 확인
- 인계 상태
  - 작업 단계와 별도 기록 / 구현 중에도 인계 준비 완료 가능
  - 두 상태로 운영: 작업 중: [도구] / 인계 준비 완료
  - 작업 시작 측은 작업 중으로 변경
  - 작업 종료 측은 결과와 인계 문서 저장 후 마지막에 인계 준비 완료 표시
  - 준비 완료 표시는 잠금이나 동시 편집 방지 수단이 아님 / 실제 보호는 한 번에 한 도구만 사용하는 운영
  - 강제 종료 등으로 준비 완료 표시가 없으면 실제 파일·실행 상태부터 확인
  - 이전 도구의 편집·명령 실행이 끝난 뒤 다음 도구의 작업 시작
- 기본 작업 폴더
  - 소스: docs/projects/PROJECT_INDEX.md와 작업별 인계 문서에 지정된 실제 경로
  - 공통 지침과 문서: `C:\Projects\Contexts`
  - 경로 안내는 도구의 실제 접근 권한 부여와 별개

## 승인 기록

- 대화와 승인 이력은 도구 간 자동 공유되지 않음 / 인계 문서에 승인 근거 기록
- 기록 항목
  - 승인 문구·시점·승인받은 도구
  - 대상 파일·함수·변경 범위
  - 승인받은 코드 또는 diff의 위치·버전
  - 승인 당시 HEAD와 관련 미커밋 변경 상태
  - 승인 이후 관련 변경과 영향
- 승인 문구만 복사하고 대상 코드 제안을 누락하는 기록 지양
- 문서에 승인 근거가 없으면 승인 미확인으로 표시
  - 현재 채팅이나 사용자 제공 근거로 확인 가능하면 문서 누락만으로 재승인 요구 불필요
  - 승인 근거를 확보할 수 없으면 코드 수정 전 사용자 확인
- 승인 후 대상 코드가 달라진 경우
  - 우선 실제 변경 차이 확인
  - 승인된 변경의 의미·범위·적용 가능성이 달라진 경우에만 사용자 재확인
  - 무관한 변경까지 일괄 재승인 대상으로 확대하지 않기
- 리뷰 피드백은 사용자 수정 승인을 대신하지 않음

## 토큰 사용량을 고려한 기록 방식

- 작업별 `HANDOFF_작업명.md` 파일을 `docs/tasks/작업명`에 저장 / Git 관리 제외
- 긴 대화 원문 대신 현재 목표·결정·승인·검증·다음 행동 기록
- 공통 규칙 전문을 인계 문서마다 복사하지 않고 원본 경로 참조
- 관련 소스 경로와 핵심 함수명을 기록하여 불필요한 재탐색 감소
- 과거 진행 로그 누적보다 최신 상태 갱신 우선 / 유효한 승인 근거는 유지
- 토큰 절약을 이유로 필수 지침 확인과 실제 코드 검증 생략 금지
- 근거 시점 표기
  - 중요한 조사 결과와 재확인 항목에 선택 적용 / 모든 줄에 강제하지 않기
  - 예: [Codex 10-22] / [Claude 10-23 재확인]
  - 오래된 조사·추정·재확인 결과 구분에 활용
  - 결과가 충돌하면 브랜치·파일 상태·검증 범위를 비교하고 근거가 충분한 결과 적용 / 날짜만으로 이전 결과를 덮어쓰지 않기
- 다른 도구의 조사 결과를 구현 판단에 사용할 때 관련 파일·확인 방법·기준 시점 확인
- 공유 규칙은 도구별 메모리에만 저장하지 않고 Contexts 원본에서 관리
  - 도구 메모리는 원본 경로 안내 용도로만 사용
- 편집 시 기존 줄바꿈 유지 / 기능 변경과 무관한 diff 방지

## 작업 관련 조사 대화의 인계 반영

- 사용자 요청 반영일: 2026-10-23
- 이미 교대 대상으로 지정된 작업에서는 일반 조사 질문·답변도 인계 대상에 포함
  - 구현 결정 전의 동작 설명·설정 방법·호출 경로·데이터 해석·기존 설명의 보정·남은 의문 포함
  - 코드 수정이나 설계 확정이 없다는 이유로 조사 결과를 인계에서 누락하지 않기
- 이후 관련 조사 답변을 마무리할 때 의미 있는 새 사실과 정정 사항을 해당 작업 HANDOFF에 반영
  - 기존 항목 갱신 우선 / 대화 원문이나 동일 설명의 반복 누적 지양
  - 확인한 사실·추정·제안·미확인 사항과 근거 파일·확인 시점 구분
  - 이전 대화에서 이어받은 결과와 이번에 직접 재확인한 결과 구분
  - 기존 계획과 충돌하는 보정은 기존 결론의 제한이나 재검토 필요성 명시
- 기록 권한은 작업 관련 조사 요약의 문서 갱신 범위
  - 조사 질문을 코드 수정 승인·구현 단계 변경·타 도구 실행 요청으로 해석 금지
  - 단독 노션 원고·문서 편집 요청의 기본 제외 규칙 유지
  - 관련 없는 모든 채팅을 자동 저장하거나 새 작업 인계를 임의 생성하지 않기
- 공유 경로는 로컬 인계 문서 / 채팅의 자동 전달이나 Claude Code의 실시간 재읽기 보장 아님
  - 다음 도구가 작업 시작·재개 시 최신 HANDOFF를 직접 읽도록 안내
  - 문서 반영 여부와 실제로 다른 도구가 읽었는지 구분하여 보고
