# PR 본문 작성 형식

- 사용자 요청 반영일: 2026-10-22
- 근거: 사용자가 붙여넣은 PR 예시의 구성과 서술 방식
- 예시의 기능명·구현 사실·설계 선택·검증 결과는 규칙으로 저장하지 않음
- PR 제목은 기존 규칙에 따라 영어로 작성
- 본문은 예시처럼 한국어 설명문을 기본으로 사용하며, 별도 요청이 있으면 해당 요청 적용
- 이 문서는 PR 원고 형식이며 PR 생성·게시 또는 Git 변경에 대한 승인으로 해석하지 않기

## 구성과 분량

- 기본 순서: 개요 → 전체 흐름 → 주요 기능 → 디버그 → 데이터 → 추가 구현 필요 사항
- 변경 규모에 맞게 필요한 항목만 사용하고 빈 항목이나 무관한 내용을 채우지 않기
- 작은 PR은 개요와 핵심 변경·검증 설명만으로 축약 가능
- 검증 설명이 길면 디버그와 별도로 검증 항목 추가 가능
- 주요 기능 아래에 기능·컴포넌트별 소제목 배치
- 파일별 변경 나열보다 기능의 책임과 사용 흐름을 중심으로 구성

## 서술 방식

- 개요에서 해결한 문제와 변경 후 동작을 먼저 설명
- 설명은 짧고 연결된 문단과 자연스러운 한국어 서술문으로 작성
- PR 본문에는 ~합니다, ~했습니다 등의 문장형 사용 가능
- Notion용 계획서의 명사형 종결 규칙을 일반 PR 본문에 일괄 적용하지 않기
- 실행 순서는 번호 목록, API·이벤트·설정 항목은 병렬 목록으로 표현
- 클래스·함수·변수·경로·명령은 인라인 코드로 구분
- 설계 이유는 해당 동작이나 변경을 설명하는 문단 가까이에 배치
- 대화에 참여하지 않은 리뷰어도 이해할 수 있도록 최종 변경 상태를 설명
- 구현 과정의 대화 이력이나 폐기한 접근은 최종 판단에 필요한 경우에만 포함
- 주요 기능의 하위 항목은 관련 있는 것만 선택하고 모든 기능에 같은 긴 양식을 반복하지 않기
- 실제 확인한 구현·검증과 미확인 사항을 구분하고 예시의 결과를 재사용하지 않기

## 항목별 작성 기준

- 개요
  - 관련 설계 문서 링크가 있으면 시작 부분에 배치
  - 문제·목적, 변경 결과, 주요 구성요소의 역할을 짧게 설명
  - 리뷰 범위를 이해하는 데 필요한 경우 포함·제외 범위와 검증 방법 요약
- 전체 흐름
  - 준비·입력부터 처리·결과까지 실행 순서대로 설명
  - 세부 함수 설명보다 구성요소 사이의 연결을 먼저 전달
- 주요 기능
  - 기능·컴포넌트 단위 소제목 아래 역할과 동작 설명
  - 필요한 경우 공개 API·입력 데이터·설정·이벤트와 호출 시점 정리
  - 내부 동작 순서가 복잡하면 동작 흐름 하위 항목 추가
  - 헬퍼와 기존 코드 연동은 별도 소제목으로 구분 가능
  - 수명·실행 권한·실패 처리·설계 이유는 변경 이해에 필요한 경우 포함
- 디버그
  - 실제 제공하는 명령·설정·로그와 확인 방법 정리
  - 수행한 검증 결과와 미수행 검증 구분
  - 디버그 기능이 존재한다는 사실을 테스트 통과로 표현하지 않기
- 데이터
  - 추가·변경된 에셋이나 설정과 연결·등록 위치 설명
  - 리뷰어 또는 사용자가 해야 하는 설정이 있으면 명시
- 추가 구현 필요 사항
  - 미구현 부분·현재 제한·임시 처리·후속 연동을 구분
  - 후속 작업을 이번 PR에서 완료한 것처럼 표현하지 않기

## 복사용 기본 틀

아래 항목은 변경 규모에 맞게 생략하거나 축약

```markdown
## 개요

[관련 문서 링크 — 있는 경우]

[해결한 문제와 변경 후 동작]
[주요 구성요소의 역할과 필요한 범위 설명]

## 전체 흐름

1. [준비 또는 입력]
2. [핵심 처리와 구성요소 간 전달]
3. [결과 또는 종료]

## 주요 기능

### [기능 또는 컴포넌트 이름]

[역할과 동작 설명]
[필요한 설계 이유와 기존 기능에 미치는 영향]

- `공개 API 또는 설정`: [용도와 사용 조건]
- `이벤트`: [발생 시점과 전달 정보]

### [다른 기능 또는 기존 코드 연동]

[변경 내용과 연결 흐름]

## 디버그

[실제 명령·설정·로그와 확인 방법]
[수행한 검증 결과와 미수행 항목]

## 데이터

[추가·변경된 데이터와 등록·설정 위치]

## 추가 구현 필요 사항

- [미구현 부분 또는 현재 제한]
- [임시 처리와 후속 연동]
```
